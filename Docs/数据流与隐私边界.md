# 数据流与隐私边界

这份说明描述当前代码实际做的事。它不是安全认证，也不是“物理上绝对不留痕迹”的证明。

## 狗证门槛

正式构建（Release）的地图默认锁住。保存犬只档案、识别到证件文字、或看到“犬证”两个字，都不会把状态变成审核通过。

状态机在 `AccessController`：

1. 没有本机档案：锁定。
2. 档案已保存：仍然锁定，等待核验。
3. 调用核验器。当前接上的是 `UnavailableDogLicenseVerifier`，固定返回不可用。不可用时失败关闭，地图继续锁定。
4. 只有核验收据明确写出“没有留存证件”，并且本机已经有档案时，状态机才接受“已核验”。应用里没有会发出这种收据的实现。
5. 调试构建里有一个单独按钮“进入演示地图（不是审核通过）”。Release 会忽略这个入口，也会忽略本机里残留的演示标记。

演示地图上的横幅一直写着：未做真实狗证核验，不是审核通过。

## 哪些内容可以留在本机

用户确认之后，`DogProfile` 可以写入 `UserDefaults` 键 `pawtrust.dog-profile.v1`。字段只有：

- 犬名（可选）
- 品种、性别、年龄段、体型
- 性格或与其他狗的相处、出行偏好
- 每个字段是“你填写的”“系统推断”还是空
- 是否允许从检索推断

年龄只存年龄段（幼年、青年、成年、老年），不存出生日期。学习默认关闭。打开后，只会在空白的推断字段里写入体型或出行偏好，不覆盖手工填写，也不上传，也不训练模型。关闭学习会清掉推断字段。

另外三个键：

- `pawtrust.favorites.v1`：收藏的地点 id
- `pawtrust.contributions.v1`：本地地点草稿和到访记录
- `pawtrust.demo-access.v1`：调试构建是否进入过演示。Release 不拿它解锁
- `pawtrust.screenshot.transient`：只有带 `-PawTrustDemoScreenshots` 的 Debug 启动会用到的临时存储，每次启动先清空。里面仍只有白名单档案，不放证件原图。Release 不会走这条路径

## 哪些内容不允许留档或外发

狗证原图、完整识别文本、主人姓名、住址、电话、证件号、犬证号、芯片号，以及这些内容的哈希，都不进入上面的档案结构。

识别流程：

1. 相册选择器只把图片数据读进内存。拍摄使用系统相机，代码没有把照片写回相册。
2. Apple Vision 在设备上读文字。
3. `LicenseExtractor` 只抄白名单字段。带有主人、电话、住址、证件、芯片等标记的整行会被跳过。
4. 原始文字数组和图片随即丢掉。切到后台、取消或令牌失效时也会丢掉。
5. 提取结果 `LicenseDraft` 本身不能编码保存。要保存必须先变成 `DogProfile`。

`LicenseDraft` 没有主人、证件号、芯片、原图或原文的字段。

相册里的原图由系统照片应用管理。清除本机档案不会删除那张原图。

内存释放、系统截图、崩溃报告和备份不能被这份代码证明为物理上的零残留。界面和这里都按这个限度来写。

## 地点规则

上海和深圳的基础地点使用公开场所的近似坐标，方便地图显示。携犬、室内、体型、围栏、放绳，以及商场里每一家店的准入，样本里都是“未知”。

未知、只有说法、有冲突、或缺少确认时间，都不能算作满足检索条件。冲突不会被后一条说法覆盖。商场整体和每一家店是分开的规则。

一句话检索由 `LocalUtteranceInterpreter` 做关键词整理，界面写的是“本地解析，不是已连接的语言模型”。没有模型密钥，也没有把档案发给外部服务。没有接 `URLSession`。

## 用户新增和到访记录

添加地点或记下一次观察，会先整理成字段，等用户确认后再写入本机。状态固定为“仅在本机·待审核·未同步”。记录里没有证件。星期习惯不会被当成日期；只有写出年月日才会留下那一天。

连续保存有 15 秒的本机间隔，最多留 30 条。这只是客户端节流，不是安全防护。

这些草稿可以出现在本地地图上，并标成草稿。它们没有进入服务器，也没有经过真实审核。

## 代码检查

`PrivacyAndAccessTests` 会扫描应用和 `PawTrustCore` 的 Swift 源文件，查看是否出现网络会话、写入相册、哈希、日志，以及白名单以外的 `pawtrust.` 存储键。测试失败只说明源码里出现了这些写法。它不能证明编译后的二进制、系统框架或设备备份没有别的副本。
